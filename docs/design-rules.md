# 設計規範：回推八步驟、兩問檢驗、設計原理

> 來源：「2026 數學遊戲」專案 `docs/遊戲設計總盤點.md`、`docs/設計檢驗-拿掉數學還玩得下去嗎.md` 與 2026-10-07 拖拉解題過程規範。
> 用法：Agent 依本頁填好 `games/<slug>/DESIGN.md`，老師審核目標、證據、誤解三欄。

核心句：**老師的專業在前四步（目標、證據、誤解、機制），AI 的價值在後四步（實作）。填好的設計表就是最好的提示詞。**

---

## 一、回推八步驟（由目標往回推，不是由好玩往前推）

| 步 | 要回答的問題 | 寫進 DESIGN.md 的內容 |
|----|--------------|------------------------|
| 1 教學目標 | 學生將能＿＿？ | 學習表現代碼（不確定寫「待查」）＋ 一句白話目標 |
| 2 評量證據＋記錄欄位 | 學生做出什麼**可觀察的數學行為**才算達標？要記成哪些欄位？ | 行為清單；每個行為對應 `mg_events` 的 `kind` 與 `payload` 欄位（Evidence-Centered Design：留痕在這一步就設計好） |
| 3 核心機制 | 把那個行為直接做成遊戲的基本操作 | 遊戲動詞、主題與機制如何內生連結、兩問檢驗結果 |
| 4 誤解→規則／誘答 | 本單元 3～5 個典型誤解是什麼？ | 每個誤解：英文代碼、規則限制或誘答選項、診斷回饋句 |
| 5 回饋與計分 | 對錯怎麼立刻看見？分數付給什麼？ | 即時回饋、高層次行為加成、錯誤代價與退路、去重防刷分 |
| 6 鷹架與分層 | 表徵如何由具體到抽象？提示怎麼給？ | 表徵階梯、三層提示（策略→指出位置→示範）、難度解鎖 |
| 7 課堂運作 | 45 分鐘怎麼用？誰推進？ | 人數結構、時間軸（含建房加入 5 分鐘）、限時推進、iPad 假設 |
| 8 資料留痕 | 遊戲結束老師拿到什麼？下一節課怎麼用？ | 報告頁內容、誤解分布、首次正確率、自願重玩指標 |

## 三、兩問檢驗

| 問題 | 擋掉的病 | 判定 |
|------|----------|------|
| ① 拿掉數學，還玩得下去嗎？ | **裝飾性遊戲化**（巧克力裹花椰菜）：答對才能擲骰／開寶箱／射擊 | 若「還玩得下去」→ 數學只是門票，回頭改機制 |
| ② 遊戲動詞 = 達標證據裡的那個行為嗎？ | **層次錯置**：要建構卻只練到辨認 | 對照第 2 步；「選出正確比例式」≠「建立比例式」 |

- 正例：座標軍艦棋拿掉「報座標」就無法指定攻擊位置；比例消除拿掉「判斷比例相等」就沒有消除規則。
- 反例：比例消除 v1 俄羅斯方塊——操作本身太好玩，搶走認知資源；v2 連連看通過第一問但只是辨認，被第二問擋下；v3 自己拖出比例式才定案。**第一版失敗是常態。**
- **T1 例外**：T1 是刻意的「評量包裝」，第一問預期不過。DESIGN.md 要寫明定位為教完後的形成性檢核，第二問改問「題目與誘答是否對準達標證據與誤解」，且拉力／傷害只來自正確作答、手速加成有上限、答錯有代價。

## 四、八條設計原理（從九款原型萃取）

1. **機制即評量**：遊戲動詞就是數學行為，每一步都是形成性評量資料點（Shute：stealth assessment）。
2. **主動建構 > 被動辨認**：讓學生自己組出式子、放出點、配出對應，而不是從選項挑答案。
3. **表徵逐步結構化 = 鷹架**：中位數偵探的文字雲 → 亂序矩陣 → 排序矩陣；三視圖的教學關 → 單人 → 競速。
4. **計分塑造行為**：分數付給高層次行為（長鏈、效率、少提示），不付給手速與運氣。
5. **誘答對準誤解**：每個干擾選項都是一個真實誤解（變號、順序顛倒、部分當全長），並有專屬診斷回饋。
6. **錯誤有代價但不毀滅**：扣分／自傷有下限、可重試、有補血或提示，讓亂試不划算但永遠有下一步。
7. **課堂節奏由系統控制**：限時自動推進、老師可提前、人數不足自動延長；遊戲配合 45 分鐘課堂。
8. **資料留痕供課後分析**：逐步紀錄、誤解分布、首次正確率；遊戲結束留下的資料才是形成性評量的本體。另記自願重玩次數（Habgood：自願投入時間是設計品質的量測）。

## 五、拖拉解題過程與精確數學表示（2026-10-07 規範）

- **拖拉的是解題過程，不只是最後答案**：學生配置已知量與未知量、建立比例／等式、配對邊角、代入、組合推理或建構圖形。把選擇題的點選改成拖答案，不算解題操作。
- **精華流程**：依教材的例題、自評與習作保留關鍵觀念與必要計算；已知數字、重複約分改為顯示鷹架，每步以 1～3 個關鍵操作為原則。
- **鷹架不可省略關鍵中介量**：例如比例求量依序建立對應式 → 代入 → 約分 → 可計算的式子；只給部分長度時先合成全長。學生不該需要離開遊戲拿筆補算。
- **操作留下可檢驗的過程**：已建立的關係可供下一步引用；記錄每步、每個卡槽的選擇、誤解、修正與提示。系統代填的量（given／derived）不算學生證據，只有學生實際放入的關係與計算才算。
- **數學表示精確**：線段上橫線、△、∠ 與頂點順序、分數上下排列、平方用上標、相似與比例對應順序一致——題目、圖、卡片、作答列、回饋與報告都一樣。
- **iPad 為主**：觸控目標 ≥ 48px；戰況浮動；題目、圖、當前步驟與卡片集中同一工作區；拖拉同時提供「點卡片再點格子」。

→ 接 Supabase 多人 → 兩分頁／兩台裝置實測 → 部署 → 班級試用 → 補留痕與老師報告
