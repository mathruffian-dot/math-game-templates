# 研習提示詞（直接複製，改＜＞內文字）

> 用法：在 Agent 開啟本資料夾後貼上。Agent 會自動讀 `AGENTS.md`；若沒讀，先說「請先閱讀 AGENTS.md」。
> 教材：把文字直接貼在提示詞後面，或把檔案放進 `materials/` 再說檔名。

---

## 第二小時：遊戲化評量（T1 紅藍格鬥・扣血對戰）

### 2-1 從教材到題庫（先確認，不急著做）
```
我是國中數學老師。下面是＜七年級 一元一次方程式＞的教材重點（或：教材在 materials/＜檔名＞）。
請照 AGENTS.md 的流程第①步：摘要教學目標、列出 3～5 個學生常見誤解（每個給英文代碼），
並建議是否適合 T1 紅藍格鬥（扣血對戰）。先不要寫程式，等我確認。
＜貼上教材＞
```

### 2-2 做成 T1 並部署
```
摘要我確認了（＜要修改的地方＞）。請用 T1（site/games/tug-of-war）做成新遊戲，slug 用＜linear-eq-tug＞：
1. 先在 games/＜slug＞/DESIGN.md 寫回推八步驟與兩問檢驗（T1 定位為教完後的形成性檢核）。
2. 題庫至少 24 題、分易中難；每題的錯誤選項各對準一個誤解代碼，並寫一句診斷回饋。
3. 數學記號依 AGENTS.md 規範（分數上下排、負數加括號等）。
4. 本機兩個分頁測試對戰後，照 docs/deploy.md 部署，給我學生端、老師端、報告網址。
```

### 2-3 題庫參數化與誤解平衡
```
學生玩兩次就背答案了。請把題庫改成參數化生成（同題型隨機係數），保證：
答案為整數或簡單分數、誘答由誤解規則自動產生（例如移項不變號、兩邊只除一邊），
且同一場不重複題目。改完跑 500 次生成檢查答案正確、誘答不等於正解，再部署並告訴我測了什麼。
```

## 第三小時：發展活動（T3 拖拉解題板）

### 3-1 把一道例題拆成步驟
```
請照 AGENTS.md 用 T3（site/games/step-board）做新遊戲，slug＜ratio-step＞。
先把下面這道例題拆成解題步驟給我看（每步 1～3 個學生要放的卡片），
標出哪些量由系統顯示（鷹架）、哪些必須學生自己拖入，關鍵中介量不能省略。
確認後再寫 DESIGN.md 與 content，並做 3 道同型題。
＜貼上例題與課本解法＞
```

### 3-2 誤解卡與三層提示
```
請在每一步加入誤解型卡片（每步至少 1 張，對準我們列的誤解代碼），
學生放錯時說出「錯在哪裡」而不只是「錯了」；提示分三層：
第 1 層提醒策略、第 2 層指出要放的位置、第 3 層示範後此步不算獨立完成。
所有拖放都記錄步驟、卡槽、選擇、誤解代碼與提示層級。做完在本機實際操作一次給我看結果。
```

### 3-3 檢查記號、iPad 與部署
```
請逐一檢查題目、卡片、回饋與報告的數學表示：線段上橫線、△、∠ 頂點順序、分數上下排列、平方上標、
比例對應順序一致。再用 1024×768 與 820×1180 檢查沒有橫向捲動、按鈕 ≥48px、拖拉可改用點選。
都通過後部署，並告訴我哪些還沒驗證。
```

## 除錯（遇到問題直接貼）

### D-1 有錯誤訊息
```
畫面出現這個錯誤（或 Console 紅字）：＜貼上錯誤全文或截圖＞
我剛剛做的操作是：＜例如按下開房、拖第二張卡片＞。
請找出原因、修正、在本機重現一次確認修好，再告訴我改了什麼。
```

### D-2 兩邊不同步或卡住
```
兩個學生分頁看到的畫面不一樣（或倒數到 0 沒有進下一輪）。
請檢查是否所有改房間的動作都走 transact、時間到是否任一端都能推進、render 是否依資料變化而不是依畫面狀態，
修好後用兩個分頁重測給我看。
```

### D-3 部署後不對
```
正式網址＜網址＞打開後＜白畫面／還是本機模式／看到舊版＞。
請依 docs/deploy.md 的常見錯誤表逐項檢查（`/api/health` 是否回應、是否跑過 D1 migrations、快取、Console 錯誤），
不要讀或要求任何 secret key，修好後重新部署並驗收。
```
