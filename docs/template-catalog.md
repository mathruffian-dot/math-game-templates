# 模板目錄與決策樹

兩軸分類：

- **定位**：**評量包裝**（教完後檢核，數學是門票；影片所說的「巧克力花椰菜」）vs **發展活動**（學習歷程本身就是遊戲，數學是引擎）。
- **互動結構**：對戰、全班主持、單人解題板、棋盤博弈、單人闖關、全班共建、盤面連線消除。

原型試玩根網址：`https://my-teaching-tools.web.app/games/`（以下簡寫 `…/games/`）。相似形格鬥場另在 Cloudflare。

---

## 決策樹

```
Q1 這個遊戲在單元中的位置？
├─ 已教完，要檢核熟練度、抓誤解（評量包裝）
│   └─ Q2 想要什麼互動？
│       ├─ 兩人或小組對戰、同時各自作答 ……………………… T1 紅藍格鬥（扣血對戰）
│       └─ 全班一起看同一題、老師主持、逐輪公布 ……………… T2 全班限時主持
└─ 正在學，要學生在遊戲中建構概念（發展活動）
    └─ Q3 這個概念的「數學動詞」最像哪一種？
        ├─ 有固定解題步驟可拆（列式、代入、直式、約分） ……… T3 拖拉建構解題板
        ├─ 位置、方向、圖形關係，且需要預判對手 ………………… T4 棋盤策略
        ├─ 規則固定、有唯一解或可驗證解、適合自己的節奏 ……… T5 單人闖關解謎
        ├─ 全班的成果彼此接續、組成共同作品 ……………………… T6 全班共建
        ├─ 全班同時看同一份資料、逐輪換表徵推理 ……………… T2 全班限時主持
        └─ 在一堆小單位裡「找出並串成成立的關係」（比例、成語、構詞…，可跨科） …… T7 盤面連線消除
```

快速判斷：時間只有一節課、第一次做 → **T1（第 2 小時）或 T3（第 3 小時）**，因為這兩型有可執行模板。國文、英文等其他科目，或只想換內容不想改機制 → **T7**（只要寫一個內容包）。

## T1 紅藍格鬥・扣血對戰（評量包裝）｜可執行：`site/games/tug-of-war/`（資料夾名稱沿用 tug-of-war）

- **適用時機**：教完一個單元或一節課後的 10～15 分鐘形成性檢核；題目有明確對錯，誤解可寫成誘答。
- **數學動詞**：判斷、計算、選出／組出正確結果（偏「提取與應用」，非建構）。
- **人數結構**：1v1～3v3 紅藍對戰；老師批量開房、QR 加入；也有單人練習。
- **原型試玩**：
  - 不等式格鬥場 https://my-teaching-tools.web.app/games/linear-inequality-fighter/demo/
  - 多項式除法格鬥場 https://my-teaching-tools.web.app/games/polynomial-division-fighter/demo/
  - 相似形格鬥場 https://math-g9-similarity-fighter.pages.dev/
- **設計要點**：傷害只來自正確作答；血量歸零立即分勝負、時間到比剩餘血量比例（實力相當也一定打得完）；誘答各對準一個誤解並有診斷回饋；答錯有代價（不攻擊＋冷卻）但不扣自己血；手速加成有上限；事件記 `err` 代碼。
- **何時不要用**：概念剛引入、學生還不會（只會放大落差、強化猜答）；題目只有一兩種、容易背答案；班上落差極大又採團隊制（弱者被看見、拖累隊友）。
- **進化方向**：把「出招」改成解題步驟（多項式除法格鬥場的直式連招），就從評量包裝往 T3 移動。模板已內建：`?play=steps&content=linear-equation|proportion|poly-division`（發展式出招，重用 T3 解題板 content，每完成一步攻擊一次）。

## T2 全班限時主持（兩者皆可）｜設計卡：`cards/T2-class-host/`

- **適用時機**：課中暖身、概念引入、全班一起討論同一份資料；需要老師暫停講解。
- **數學動詞**：估計、推理、比較（同一份資料在不同表徵下重新判斷）。
- **人數結構**：全班一場，老師投影主畫面，學生各自作答。
- **原型試玩**：中位數偵探 https://my-teaching-tools.web.app/games/median-detective/demo/（需一台當老師主持、其他分頁當學生）
- **設計要點**：表徵逐輪結構化（文字雲 → 亂序矩陣 → 排序矩陣）；底分隨資訊增加而遞減；只獎勵答對者的速度；限時自動推進、老師可提前。
- **何時不要用**：需要長時間個別操作的題目；全班網路不穩（全班卡在同一場）；每人進度差異大的練習。

## T3 拖拉建構解題板（發展活動）｜可執行：`site/games/step-board/`

- **適用時機**：例題教學後、學生第一次獨立做同類題；有固定程序（列式、移項、代入、直式、比例求量）。
- **數學動詞**：建構——配置已知／未知量、建立等式或比例式、代入、約分、組合結果。
- **人數結構**：單人為主；可以完成題數或傷害接到對戰（多項式除法格鬥場就是 T3＋T1）。
- **原型試玩**：
  - 多項式除法格鬥場（直式拖拉）https://my-teaching-tools.web.app/games/polynomial-division-fighter/demo/
  - 相似形格鬥場（解題板）https://math-g9-similarity-fighter.pages.dev/
- **設計要點**：拖的是過程不是答案；每步 1～3 個關鍵操作；已建立的關係留在畫面；誤解型卡片＋診斷回饋；三層提示；接受等價寫法。
- **何時不要用**：沒有可拆的步驟（純事實記憶）；步驟太長且每步都只是機械抄寫（先精簡流程）；要評量完全獨立的自由作答（解題板有鷹架，需搭配紙筆出口題）。

## T4 棋盤策略（發展活動）｜設計卡：`cards/T4-board-strategy/`

- **適用時機**：坐標、對稱、方程式圖形、距離等「位置」類概念的應用與熟練。
- **數學動詞**：定位、預測、規劃（用數學規則決定合法的下一步，並推測對手）。
- **人數結構**：2～4 人一房，回合制；可共用一台 iPad 熱座或各自裝置。
- **原型試玩**：
  - 座標軍艦棋 https://my-teaching-tools.web.app/games/battleship/?ns=public
  - 對稱棋三人戰 https://my-teaching-tools.web.app/games/line-symmetry/symbattle/?ns=public&demo=3
- **設計要點**：唯一合法的移動方式就是數學操作（報座標、擺對稱軸）；高效率的數學行為（方程式一次掃多格）給較高回報；先後手公平；一局 10～15 分鐘。
- **何時不要用**：概念尚未熟練（策略層會壓過數學層）；回合等待太久（3 人以上要控制單回合時間）；只有一兩種合法走法（沒有策略空間）。

## T5 單人闖關解謎（發展活動）｜設計卡：`cards/T5-solo-puzzle/`

- **適用時機**：課前自學、課堂前 10 分鐘暖身、補救教學、回家自主練習。
- **數學動詞**：判斷、建構、驗證（對摺、堆疊、消去），配合可驗證的規則逐關升級。
- **人數結構**：單人，自己的節奏；可選擇性上傳歷程與排行榜。
- **原型試玩**：
  - 鏡像學徒 https://my-teaching-tools.web.app/games/line-symmetry/solo/?ns=public
  - 對稱棋孔明棋消除 https://my-teaching-tools.web.app/games/line-symmetry/sympieces/?ns=public
  - 三視圖建築師 https://my-teaching-tools.web.app/games/three-view/
- **設計要點**：反向生成保證有解；系統用「摺給你看」這類動畫做回饋本體；提示換扣分；卡死偵測＋復原；記錄自願重玩。
- **何時不要用**：需要同儕互動或討論的概念；需要老師即時掌握全班節奏的時段（改 T2）。

## T6 全班共建（發展活動）｜設計卡：`cards/T6-class-build/`

- **適用時機**：單元綜合活動；同一概念有多種建構方式，彼此成果可以互相接續（甲的成品是乙的題目條件）。
- **數學動詞**：建構、接續、論證（用別人的成果當已知條件再建構）。
- **人數結構**：全班一房，個人計分、共享作品；老師分區推進。
- **原型試玩**：相似島 https://my-teaching-tools.web.app/games/similarity-island/
- **設計要點**：每題只控制一個目標；正確成果自動成為他人下一題來源；區分系統給定（given／derived）與學生操作；全班狀態精簡、詳細歷程放事件表。
- **何時不要用**：第一次做遊戲（技術與課堂運作最複雜）；班級少於 15 人（共建感不足）；概念沒有「接續」性質。

## T7 盤面連線消除（發展活動，跨科）｜可執行：`site/games/chain-match/`

- **適用時機**：學過一組關係之後的熟練與辨別（比例式、成語與錯別字、字首字根字尾…）；課中 5～10 分鐘一輪，可重玩。
- **數學（學科）動詞**：在盤面上**找出並串成一組成立的關係**（建構）。消除規則本身就是學科關係，拿掉判斷就沒有遊戲。
- **人數結構**：單人（3 分鐘自主練習）；老師開房控制時間，學生各自盤面，看板即時看誤解分布。
- **原型試玩**：比例消除 https://my-teaching-tools.web.app/games/ratio-tetris/
- **內建內容包**：數學比例式（`math/ratio`）、國文成語（`chinese/idiom`，錯別字誘答）、英文構詞（`english/affix`，否定字首誘答）。新科目只要寫一個內容包（方塊內容＋`check()` 判斷規則＋誤解 `kind`），見 `site/games/chain-match/README.md`。
- **設計要點**：每條鏈都是學科關係；失敗要說出錯在哪（`reversed` 與 `mismatch` 分開）；誘答鏈對準真實誤解；不自動連鎖；保證永遠有路；iPad 預設點選模式（避免連續觸控拖曳的記憶體問題）。
- **誠實評估**：國文成語包偏記憶提取＋辨別錯別字，屬建構拼寫但層次低於數學包；英文構詞包為規則應用。DESIGN.md 要逐包寫兩問檢驗。
- **何時不要用**：關係只能「辨認」不能「串出來」（例如是非題）；一條鏈超過 8 格；需要多步推理與計算過程（改用 T3）。
